# Flavors Skill

## How Flavors Work

This project uses a **two-layer flavor system**:

1. **Dart layer** — Custom `Flavor` enum + `FlavorConfig` singleton (reads Flutter's built-in `appFlavor` from `--flavor` flag)
2. **Native layer** — Generated by `flutter_flavorizr` (Android productFlavors, iOS schemes + xcconfigs)

The Dart side lives in `lib/src/core/flavors/` and the native config lives in `flavorizr.yaml` at the project root.

### Key files

| File | Role |
|------|------|
| `flavorizr.yaml` | Defines flavors for native code generation |
| `lib/src/core/flavors/flavor.dart` | `Flavor` enum with label, seedColor, isDev |
| `lib/src/core/flavors/flavor_config.dart` | Singleton that holds the current flavor at runtime |
| `lib/main.dart` | Reads `appFlavor` → calls `FlavorConfig.initialize()` |
| `android/app/flavorizr.gradle.kts` | Generated Android productFlavors |
| `ios/Runner.xcodeproj/xcshareddata/xcschemes/` | Generated iOS schemes (dev.xcscheme, prod.xcscheme) |
| `ios/Flutter/` | Generated flavor-specific xcconfig files |

## Adding a New Flavor (e.g., "staging")

### Step 1: Update `flavorizr.yaml`

Add the new flavor entry:

```yaml
flavors:
  dev:
    app:
      name: "Riverpod Starter (Dev)"
    android:
      applicationId: "com.starter.riverpod_architecture_starter.dev"
    ios:
      bundleId: "com.starter.riverpodArchitectureStarter.dev"
  staging:                                              # NEW
    app:
      name: "Riverpod Starter (Staging)"
    android:
      applicationId: "com.starter.riverpod_architecture_starter.staging"
    ios:
      bundleId: "com.starter.riverpodArchitectureStarter.staging"
  prod:
    app:
      name: "Riverpod Starter"
    android:
      applicationId: "com.starter.riverpod_architecture_starter"
    ios:
      bundleId: "com.starter.riverpodArchitectureStarter"
```

### Step 2: Update the Dart `Flavor` enum

File: `lib/src/core/flavors/flavor.dart`

```dart
enum Flavor {
  dev,
  staging,  // NEW
  prod;

  String get label => switch (this) {
    dev => 'DEV',
    staging => 'STAGING',  // NEW
    prod => 'PROD',
  };

  Color get seedColor => switch (this) {
    dev => Colors.orange,
    staging => Colors.teal,  // NEW
    prod => Colors.blue,
  };

  bool get isDev => this == dev || this == staging;  // Update if staging shows debug features
}
```

### Step 3: Re-run flutter_flavorizr (native-only processors)

```bash
dart run flutter_flavorizr -p assets:download,assets:extract,android:androidManifest,android:flavorizrGradle,android:buildGradle,android:dummyAssets,ios:xcconfig,ios:buildTargets,ios:schema,ios:dummyAssets,ios:plist,ios:launchScreen,assets:clean -f
```

**Important:** Only use native processors. Do NOT run `flutter:flavors`, `flutter:app`, `flutter:pages`, or `flutter:main` — they would overwrite our custom Dart code.

### Step 4: Run with the new flavor

```bash
flutter run --flavor staging
```

## Removing a Flavor

### Step 1: Remove from `flavorizr.yaml`

Delete the flavor entry from the YAML file.

### Step 2: Remove from the Dart `Flavor` enum

Remove the value from the enum and all corresponding `switch` cases in `flavor.dart`.

### Step 3: Re-run flutter_flavorizr

Same command as above — it will regenerate native configs without the removed flavor.

### Step 4: Clean up leftover native files

Flavorizr may leave behind files for the removed flavor. Delete manually:
- `android/app/src/<flavor>/` (Android source set)
- `ios/Runner.xcodeproj/xcshareddata/xcschemes/<flavor>.xcscheme` (iOS scheme)
- `ios/Flutter/<flavor>Debug.xcconfig`, `<flavor>Release.xcconfig`, `<flavor>Profile.xcconfig`
- `ios/Runner/Assets.xcassets/<flavor>.appiconset/` (if generated)
- `ios/Runner/<flavor>LaunchScreen.storyboard` (if generated)

### Step 5: Search for references

Search the codebase for any hard-coded references to the removed flavor name.

## Gotchas

- The `appFlavor` global variable is set by Flutter at compile time from `--flavor`
- `FlavorConfig.initialize()` MUST be called before any widget is built
- Android/iOS flavor names must match the `Flavor` enum values exactly (lowercase)
- Always use native-only processors with flavorizr — never the `flutter:*` processors
- The `flavorizr.yaml` lives at project root, NOT inside `pubspec.yaml` (the old inline format is deprecated)
- After re-running flavorizr, verify with `flutter run --flavor <name>` on both platforms
